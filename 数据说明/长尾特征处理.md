# 长尾特征处理

脚本：`scripts/transform_tail_features.py`。阈值只用训练集样本计算，再原样用于验证集和测试集。
样本 = 有成交的分钟，且不在换月前 3 天（`pre_roll_3d = 0`）；补出的分钟（`is_filled = 1`）同样做变换，但不参与计算阈值。
输入 `features/features_1min.parquet`（不修改），输出 `features/features_1min_tailfix.parquet`（列名不变，只有下表 8 列改变），阈值与统计见 `features/tail_transform_params.csv`。
之后的标准化见 `scripts/standardize_features.py`（输出 `features/features_1min_scaled.parquet`），同样只用训练集样本的均值和标准差。
"原因"一列由训练集样本中最极端的 0.1%（每个特征 232 个）出现的时间核实，时间为美东时间。

表中统计都用训练集样本（232,608 个）。取对数的特征（spread_atr、relvol_60、atr_rel、vol_ratio_5_60）处理后为对数单位，括号内换算回原单位。缩尾后的取值范围就是处理前 1% 与 99% 分位数，每个特征都有 1% 的训练样本落在下限、1% 落在上限。取对数和缩尾都不改变大小顺序，所以中位数（换算回原单位）前后不变。
补出的分钟成交量为 0，relvol_60 = 0，取对数前先设一个极小的下限（10⁻¹²），再被缩尾到下限阈值。

**和剔除换月前 3 天之前相比：** spread_atr 的峰度从 2,680 降到 496，99% 分位数从 4.25 降到 0.55，说明它原来的长尾主要来自换月前夕；其余特征的阈值变化不大。

## 说明

- 剔除换月前 3 天后，spread_atr 处理后的峰度从 7.6 降到 −0.19，不再在上限处堆积。
- 缩尾会让 d_open、d_high、d_low 在重新开盘跳空时的大小信息丢失（只保留方向和"超过阈值"）。如果需要，可以另加一个"重新开盘第一分钟"的 0/1 标记。
- d_open 在验证集被缩尾的比例约为训练集的 2.3 倍，说明验证期这个特征的极端值更多，评估时可以留意。
- spread_atr 的极端值有 44% 落在换月前 3.5 天，刚好在 3 天剔除范围之外。如果之后想更彻底，可以考虑把剔除范围放宽到 4 天。
